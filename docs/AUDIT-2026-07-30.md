## Confirmed defects and remediation

### 1. False-green automated tests — Critical

The solution did not include all test projects while CI used `--no-build`. A successful workflow did not prove that tests were built or executed.

Remediation:

- Added Core, App, and UI test projects to the solution.
- Built the complete solution with warnings treated as errors.
- Executed Core and App tests with TRX output.
- Required exactly two non-empty result files with zero failures.
- Uploaded test evidence from every run.

### 2. Concurrent scheduler mutation — High

Timer callbacks, idle monitoring, UI commands, session events, and power events could mutate the same scheduler from multiple threads.

Remediation:

- Serialized scheduler mutations onto the application synchronization context.
- Rejected overlapping timer callbacks.
- Routed Windows session and power events through the WPF dispatcher.
- Persisted cloned state instead of mutable live objects.

### 3. Display disconnect and monitor power recovery — High

The application subscribed to display-change events but did nothing. A fullscreen overlay could remain on stale monitor coordinates or lose its valid visual surface after monitor off/on, disconnect/reconnect, sleep/resume, or unlock.

Remediation:

- Added active-overlay recovery for display topology changes, resume, and unlock.
- Debounced repeated Windows display events for 750 ms.
- Used native physical monitor bounds for fullscreen positioning.
- Refreshed the monitor snapshot and WPF visual surface.
- Recreated an invalid or closed overlay while preserving break type, countdown, activity, and glass clarity.
- Added a lost-overlay recovery regression test.

### 4. Mixed-DPI fullscreen placement — High

Physical monitor pixels were assigned directly to WPF device-independent coordinates, which could place overlays outside the visible display on mixed-DPI systems.

Fullscreen placement now uses native window positioning with physical monitor bounds.

### 5. Destructive settings recovery — High

One invalid persisted setting could reset all user preferences.

Remediation:

- Added field-by-field normalization.
- Expanded partial JSON recovery to every current settings field.
- Preserved unrelated valid preferences.
- Added strict invariant work-time parsing and regression tests.

### 6. Invalid work-hour input saved as midnight — High

Invalid text could silently become `00:00`.

Remediation:

- Accept only valid `H:mm` or `HH:mm` values.
- Block save when either value is invalid.
- Show a dedicated validation message.

### 7. Dirty upgrades preserved broken settings and state — High

The previous installer deliberately preserved `%LocalAppData%\Awayra`. Reinstalling or upgrading therefore carried forward settings, scheduler state, statistics, logs, startup registration, shortcuts, and stale program files.

Awayra 1.0.5 now uses a clean replacement policy:

- force-close any running Awayra process
- use a fixed per-user install directory
- ignore previous directory and task selections
- create a new uninstall log rather than appending to the old log
- delete the old program directory before copying files
- delete local and roaming Awayra data
- delete old settings, state, statistics, logs, onboarding markers, shortcuts, and startup registration
- initialize a fresh onboarding marker
- remove Awayra-owned data during uninstall

Automated upgrade validation now:

1. creates simulated legacy program files, settings, state, statistics, logs, roaming data, and startup registry data
2. installs Awayra 1.0.5 and verifies every legacy artifact was removed
3. creates a second generation of stale data
4. installs the same version again to simulate an upgrade or reinstall
5. verifies a second clean reset
6. uninstalls and verifies the application and all Awayra-owned data are removed

Result: `CLEAN UPGRADE INSTALLER TEST: PASSED`.

### 8. Shutdown could leave a trayless process — High

Shutdown cleanup now runs in `finally`, unregisters system events, disposes pipes, releases the single-instance mutex, and terminates even if persistence fails.

### 9. Unknown UI exceptions were swallowed — High

Only the explicit dashboard XAML fallback is handled. Unknown dispatcher exceptions are logged and allowed to terminate rather than leaving corrupted runtime state.

### 10. Time-dependent About test was flaky — Medium

The old test assumed a WPF window would always open and close in under two seconds. It now verifies that exact scheduler due timestamps and state fields remain unchanged, independent of runner speed.

### 11. Dependency maintenance and UI test toolchain — Medium

- Added GitHub Actions dependency monitoring.
- Aligned the UI test MSTest stack with the Core and App projects.

## Remaining risks

### Physical display validation

Hosted CI cannot electrically power-cycle a real monitor. Version 1.0.5 still requires a physical Windows test for repeated monitor off/on, disconnect/reconnect, sleep/resume, session unlock, and mixed-DPI multi-monitor behavior.

### Production signing

The current installer is unsigned. Authenticode signing is still required before broad public distribution to avoid Windows publisher warnings.

### Workflow hardening

Publishing workflows can later be split from read-only pull-request validation and security-sensitive Actions can be pinned to reviewed immutable commit SHAs.

## Required physical acceptance pass

Before merge:

- install Awayra 1.0.5 over the previously installed version and confirm old settings are gone
- confirm first launch starts from default settings
- test Eye Reset and Move Break manually
- power the monitor off and on repeatedly during an active overlay
- test sleep/resume and lock/unlock during an active overlay
- test close-to-tray, pause/resume, startup registration, and quit
- uninstall and confirm `%LocalAppData%\Awayra` and `%LocalAppData%\Programs\Awayra` are removed

## Decision

The automated code, test, package, installer, clean-upgrade, and uninstall gates are green. The branch is ready for physical Windows acceptance testing. Merge only after the real monitor and installed-upgrade checks pass.
