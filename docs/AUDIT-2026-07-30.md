## Executive result

The audit found multiple defects that were hidden by incomplete CI coverage. The most serious issue was a false-green Windows workflow: test projects were not part of the solution, while test commands used `--no-build`. GitHub Actions could therefore report success without producing test discovery or result evidence.

The branch now builds the complete solution, executes the Core and App test assemblies, validates the generated TRX files, uploads the test evidence, builds the NuGet package, and produces the Windows installer artifact.

## Confirmed defects and remediation

### 1. False-green automated tests — Critical

**Problem**

`Awayra.sln` contained only the application and core projects. Core, App, and UI test projects were outside the solution. The Windows workflow built that incomplete solution and then invoked test projects with `--no-build`. A successful command exit did not prove that tests were discovered or executed.

**Remediation**

- Added all three test projects to `Awayra.sln`.
- Made the workflow build the complete solution with warnings treated as errors.
- Added explicit Core and App test execution after the build.
- Added TRX result generation.
- Added a gate requiring exactly two TRX files and more than zero tests in each file.
- Added test-result artifact upload.
- Hardened `scripts/test.ps1` and `scripts/verify-change.ps1` with the same evidence requirement.

### 2. Concurrent scheduler mutation — High

**Problem**

`System.Timers.Timer` callbacks, idle monitoring, UI commands, session events, and power-resume events could mutate the same `BreakScheduler` instance from different threads. This created race conditions around break start/end, pause state, due times, diagnostics, and persistence.

**Remediation**

- Capture the application synchronization context during initialization.
- Serialize timer, idle, and diagnostics callbacks onto that context.
- Reject overlapping timer callbacks with interlocked pending flags.
- Route session-lock/unlock and power-resume scheduler ticks through the WPF dispatcher.
- Start periodic timers only after settings, state, statistics, idle state, diagnostics, and initial persistence are initialized.
- Persist cloned scheduler and statistics snapshots instead of serializing mutable live objects.

### 3. Destructive settings recovery — High

**Problem**

One invalid persisted setting could make the application discard all user preferences and replace the entire configuration with defaults. Partial JSON recovery handled only a small subset of fields.

**Remediation**

- Added field-by-field normalization for intervals, durations, snooze, idle threshold, work hours, glass clarity, theme, and schema version.
- Expanded partial JSON recovery to all current settings fields.
- Preserved unrelated valid preferences when one field is corrupt.
- Added strict invariant time parsing.
- Added regression tests for invalid-field recovery and partially corrupt JSON.

### 4. Invalid work-hour text saved as midnight — High

**Problem**

The settings view ignored the result of `TimeOnly.TryParse`. Invalid text such as `99:99` could silently become `00:00` and be saved.

**Remediation**

- Accept only `H:mm` or `HH:mm` using invariant parsing.
- Stop the save operation when either time is invalid.
- Display a dedicated validation message.
- Added an App regression test proving invalid input is neither persisted nor treated as a successful save.

### 5. Incorrect validation copy — Medium

**Problem**

The validator required a minimum break duration of 10 seconds, while the UI told users the minimum was 5 seconds.

**Remediation**

Both Eye Reset and Move Break messages now state the actual 10-second minimum.

### 6. Onboarding repeated after upgrades — Medium

**Problem**

The installer recreated `onboarding.pending` during every installation, including upgrades, despite onboarding being intended as a one-time first-install experience.

**Remediation**

The installer now creates the marker only when neither persisted settings nor an existing onboarding marker is present.

### 7. Shutdown could leave a trayless process running — High

**Problem**

The tray was disposed and the host stopped before persistence completed. If persistence or logging threw an exception, the final application shutdown and resource cleanup might never execute.

**Remediation**

- Wrapped graceful shutdown in `try/catch/finally`.
- Always unregister system events, dispose UI-test pipes, release the single-instance mutex, and terminate the application.
- Log persistence failures without allowing them to block exit.

### 8. Unknown UI exceptions were swallowed — High

**Problem**

Every dispatcher exception was marked handled. Continuing after an unknown unhandled exception can leave the WPF UI or scheduler in a corrupted partial state.

**Remediation**

Only the explicitly supported dashboard XAML fallback is handled. Unknown dispatcher exceptions are logged and allowed to terminate normally.

### 9. Dependency maintenance gap — Medium

**Problem**

Dependabot monitored NuGet packages but not GitHub Actions dependencies.

**Remediation**

Added monthly grouped updates for GitHub Actions.

### 10. UI test toolchain drift — Medium

**Problem**

The UI test project used an older MSTest stack than the Core and App test projects.

**Remediation**

Aligned UI tests to MSTest 4.0.2. Two analyzer rules are locally suppressed only in the desktop UI test project because its assertions intentionally include diagnostic messages and its process-level tests use hard external timeouts. All other warnings remain enabled and the project is built by the solution gate.

## Remaining risks

### Production signing — High before public distribution

The build system supports Authenticode signing when signing certificate and timestamp environment variables are configured. The current pull-request artifact should be treated as unsigned unless its `BUILD-INFO.txt` and Windows signature properties explicitly confirm otherwise. Unsigned public installers can trigger Windows publisher warnings.

### Interactive desktop validation — Medium

Hosted CI proves compilation, logic tests, package creation, and installer creation. It does not replace a Windows 10/11 device pass for tray behavior, multi-monitor overlays, DPI scaling, sleep/resume, session lock/unlock, startup registration, upgrade installation, and uninstall behavior.

### Workflow write permissions — Medium

The release workflow requests `contents: write`, and the package workflow requests `packages: write` and `statuses: write`. Their publishing steps are conditionally skipped for pull requests, but a stronger design would separate read-only pull-request build workflows from write-enabled main-branch publishing workflows.

### Action pinning — Medium

Actions currently use major-version tags such as `actions/checkout@v4`. Dependabot now tracks these dependencies, but security-sensitive workflows can be hardened further by pinning actions to reviewed immutable commit SHAs.
